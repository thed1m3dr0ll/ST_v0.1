# Для разработчика: контент и админка

Сайт — статический [Astro 7](https://astro.build) (`npm run build` → `dist/`, обычные HTML-файлы).
Часть контента вынесена в JSON и редактируется заказчиком через **[Decap CMS](https://decapcms.org/docs/)**
по адресу `/admin/`. Админка — git-based: она не хранит данные у себя, а коммитит JSON и картинки
в репозиторий. После коммита хостинг пересобирает сайт.

Инструкция для заказчика — `../АДМИНКА — как пользоваться.md`.

## Что уже сделано

| Раздел | Данные (редактирует админка) | Код, который их читает |
|---|---|---|
| Вакансии | `src/content/vacancies/*.json` — один файл на вакансию | `src/data/vacancies.ts` → `pages/careers.astro`, `pages/careers/[slug].astro` |
| События | `src/content/events/*.json`, фото — `src/assets/events/` | `src/data/events.ts` → `pages/about/events.astro` |
| Объекты | `src/content/objects/<папка>/index.json` + фото в той же папке | `src/data/projects.ts` → `pages/projects/`, главная, «Партнерам», `ObjectModal`, `ProjectCard` |
| Контакты | `src/content/contacts.json` | `src/data/site.ts` (объект `site` — та же форма, что и раньше) |
| Сертификаты | `src/content/certificates.json`, картинки — `src/assets/company-certificates/` | `src/data/certificates.ts` → `components/home/Certificates.astro` |

- Модули в `src/data/*.ts` читают JSON через `import.meta.glob` / `import` при сборке. Они устойчивы к неполным
  данным: пустые поля и списки не выводятся, а объект без фото или вакансия без названия пропускаются, а не
  роняют сборку. Экспортируемые типы и формы данных прежние, компоненты почти не менялись.
- Списки пунктов (`duties`, `requirements`, `conditions` у вакансий, `works` у объектов) хранятся одной строкой,
  пункт = строка текста (в админке — одно многострочное поле). Разбор — `src/data/lines.ts` (понимает и массив).
- `published: false` — запись скрыта с сайта (на её страницу тоже не попасть). `order` задаёт сортировку
  (по возрастанию), при равных значениях сортировка по названию.
- **Вакансии.** Адрес страницы `/careers/<slug>/` — транслитерация названия (`slugify` в `vacancies.ts`).
  Имя JSON-файла ни на что не влияет. Ссылка `hh` чистится от query-параметров у доменов `*.hh.ru`.
  Если `hh` пусто, «Откликнуться» открывает форму резюме (`ResumeModal`, `data-resume="Отклик: …"`).
- **Объекты.** slug = имя папки (новые папки админка называет датой-временем, например `20261020-094253`).
  В `photos` пути вида `/src/content/objects/<папка>/<файл>`, код берёт только имя файла и ищет его
  в папке объекта.
- **События.** Поле `body` — HTML из своего виджета `rich-text` (`public/admin/rich-text.js`, подключён
  в `pages/admin/index.astro`): `<p>`, `<br>`, `<b>`, `<i>`, `<u>`, `<span style="color:…">`, цвета только
  из списка. На сайте HTML чистится ещё раз по белому списку (`cleanHtml` в `events.ts`), списки цветов
  в обоих файлах должны совпадать. Дата — поле `day`, а не `date`: из поля `date` Decap взял бы
  `{{year}}{{month}}{{day}}` для имени файла. У открытого события адрес `/about/events/#<имя файла>`.
- **Карусель на «Партнерам»** берёт 4 объекта по slug (`pages/partners.astro`). Недостающие пропускаются.
  Фото для полос на «Партнерам» скопированы отдельно в `src/assets/partners/bands/`.
- **Интеграция `tools/admin-uploads.mjs`** (подключена в `astro.config.mjs`) при старте dev/build и при
  каждом сохранении в dev:
  - уменьшает загруженные фото больше 2000 px (sharp, на месте, EXIF-поворот, метаданные удаляются)
    в `src/content`, `src/assets/company-certificates`, `src/assets/uploads`;
  - дописывает имя папки в пути `photos` у только что созданных объектов (Decap при создании записи
    ещё не знает `{{dirname}}`).

  При сборке на CI это тоже срабатывает, но изменённые файлы там не коммитятся. Это не страшно: сайт
  соберётся правильно, а фото на всякий случай ужмёт и сам Astro (WebP).

## Файлы админки

```
src/pages/admin/index.astro     страница /admin/ (пустой HTML + скрипт Decap)
public/admin/config.yml         настройка коллекций и полей, РУССКИЕ подписи и подсказки
public/admin/decap/             сама Decap CMS 3.17.1 (локальная копия, без CDN; обновить: npm run cms:update)
tools/cms-server.cjs            локальный прокси decap-server (npm run cms), слушает 127.0.0.1:8081
tools/copy-decap.cjs            копирует decap-cms из node_modules в public/admin/decap/
tools/admin-uploads.mjs         интеграция Astro, см. выше
```

Локально заказчик запускает `Запустить сайт.bat`, который поднимает `npm run dev` и `npm run cms`.
`local_backend: true` в `config.yml` включает работу через decap-server (только на localhost),
без логина, с записью прямо в файлы.

## Что нужно сделать при публикации

1. **Корень репозитория — папка `site`.** Все пути в `config.yml` (`folder`, `media_folder`,
   `public_folder`) — от неё. Если в репозитории `site` окажется подпапкой, допишите `site/` в начало
   `folder`, `media_folder` и `file`, а в `public_folder` ничего не меняйте: это путь внутри проекта Astro.
2. **Сборка на хостинге из git:** build `npm run build`, publish `dist`, Node 22+. Подойдёт любой хостинг
   с автосборкой при push: Netlify (сайт сейчас там), Cloudflare Pages, Vercel, свой CI → rsync и т. п.
3. **Блок `backend` в `public/admin/config.yml`:** заменить заглушку `OWNER/REPO` и выбрать способ входа.
   Варианты (документация: https://decapcms.org/docs/backends-overview/):
   - **GitHub** (`name: github`) нужен OAuth-провайдер. На Netlify он встроен (Site settings →
     Access & security → OAuth → GitHub). Вне Netlify подойдёт любой готовый OAuth-прокси для Decap,
     например на Cloudflare Workers, и `base_url` на него.
   - **GitLab** (`name: gitlab`, `auth_type: pkce`, `app_id: …`) работает без своего сервера:
     достаточно OAuth-приложения в GitLab (подходит и self-hosted GitLab, тогда ещё `api_root`/`base_url`).
   - **Gitea / Forgejo** (`name: gitea`) — тоже через OAuth-приложение.
   - Вместо Decap можно поставить **Sveltia CMS**, она понимает тот же `config.yml`.
   `local_backend: true` можно оставить: в продакшене он не срабатывает (только на localhost).
4. **`decap-server` никогда не запускать на сервере.** У него нет авторизации, он только для локальной работы.
5. Перед запуском поиска: `indexable: true` в `src/data/site.ts` и убрать запрет в `public/robots.txt`.
   Страница `/admin/` закрыта мета-тегом `noindex`.
6. **SEO при запуске** (на steklyanika.ru сейчас работает старый сайт):
   - **301-переадресации со старых адресов страниц на новые** — иначе пропадут позиции, которые набрал
     старый сайт. Список старых адресов — из Яндекс.Вебмастера / Search Console или обходом старого сайта.
   - Карта сайта (`@astrojs/sitemap`, ссылка на неё — строкой `Sitemap:` в `robots.txt`) и
     `<link rel="canonical">` в `src/layouts/Base.astro`. Домен уже задан: `site` в `astro.config.mjs`.
   - HTTPS, один вариант адреса (с www или без), остальные — 301 на него.
   - Яндекс.Вебмастер и Google Search Console: подтвердить сайт, отправить карту сайта, указать регион.
   - Номер Яндекс.Метрики — `TRACKER_IDS` в `src/scripts/trackers.ts`.
   Уже сделано: превью ссылок (og-теги, картинка 1200×630), данные о компании schema.org (`src/data/seo.ts`,
   берутся из контактов), документы и 404 — `noindex, follow` (проп `noindex` у `Base`).

После этого заказчик правит контент на боевом сайте по адресу `/admin/`, а не локально. Если до переезда
она продолжала править у себя, перенесите свежие `src/content/` и `src/assets/company-certificates/`.

## Добавить в админку новый раздел

1. Вынести данные из `src/data/<раздел>.ts` в `src/content/...json`, а в `.ts` оставить чтение
   (по образцу `vacancies.ts` / `certificates.ts`).
2. Описать коллекцию в `public/admin/config.yml` (типы полей: https://decapcms.org/docs/widgets/).
3. Если в разделе есть картинки, добавить их папку в `DIRS` в `tools/admin-uploads.mjs`.

Вне админки остаются тексты секций (`src/components/**`), услуги (`src/data/services.ts`),
системы (`src/data/systems.ts`), факты и меню (`src/data/site.ts`) и кейсы на главной (`src/data/cases.ts`).
Скрипты `tools/prep-*.{cjs,py}` для массовой подготовки фото по-прежнему работают
(`prep-objects.cjs` пишет в `src/content/objects/<slug>/` и обновляет `photos` в `index.json`).

## Cookie, аналитика и реклама

Выбор посетителя управляет загрузкой сервисов. Устройство:

| Файл | За что отвечает |
| --- | --- |
| `src/components/CookieBanner.astro` | баннер; закрывается только кнопками «Принять» и «Отклонить», крестика нет по решению заказчика |
| `src/scripts/cookies.ts` | запись выбора, проверка `hasConsent()`, версия согласия, точка передачи на сервер |
| `src/scripts/trackers.ts` | номера сервисов, запуск, остановка, удаление их данных, цели `trackGoal()` |

Модель согласия единая: аналитика и реклама разрешаются и запрещаются вместе.

**Правило:** аналитика и реклама подключаются только через `trackers.ts`. Код из кабинетов нельзя вставлять в `Base.astro`, HTML
или другие компоненты. Части `<noscript>` не добавлять: они срабатывают без согласия. Цели отправлять только через `trackGoal()`.

### Подключение Яндекс.Метрики и пикселя VK

Подключать только после отдельного согласования.

1. Вписать номера в `TRACKER_IDS` в `src/scripts/trackers.ts`.
2. Сверить `start()` с актуальным кодом из кабинета сервиса: адрес скрипта, настройки счётчика.
3. У пикселя VK проверить на реальной странице, какие cookie он ставит, и уточнить `cookies` и `storage` в его записи.
   Официального списка не нашлось, сейчас указан шаблон `tmr_`.
4. Вебвизор в Метрике сейчас выключен. Перед включением оценить запись данных форм и соответствие политике.
5. Поднять `CONSENT_VERSION` в `src/scripts/cookies.ts`, чтобы все посетители сделали выбор заново.
6. Проверить в DevTools (Network, Application): до «Принять» и после «Отклонить» нет запросов к `mc.yandex.ru` и `top-fwz1.mail.ru`.

При смене редакции Политики cookie обновить `POLICY_EDITION`. При существенной смене условий или состава сервисов поднять `CONSENT_VERSION`.

### Что делается при отказе

Сервисы получают команду остановки (у Метрики `disableYaCounter<номер>` и `destruct`), затем удаляются их cookie и записи
в localStorage и sessionStorage. Если сервис работал на этой странице, она перезагружается: загруженный скрипт иначе не выгрузить.
Cookie на доменах самих сервисов (`mc.yandex.ru`, `mail.ru`) и уже отправленные данные сайт удалить не может.

### Перенос записи согласия на сервер

Запись в localStorage не подтверждает согласие юридически: посетитель может её удалить или изменить. На постоянном хостинге нужно
сделать приём записей (например `POST /api/consent`), хранить их на сервере и включить отправку в `sendConsentRecord()` в `cookies.ts`.
В записи уже есть номер, версия, редакция политики, решение, категории, время и источник.

### Проверка без настоящих сервисов

В `npm run dev` в консоли браузера выполнить `localStorage.setItem('stk-test-trackers', '1')` и обновить страницу.
Появятся два тестовых сервиса, они обращаются только к самому сайту (`/__test-tracker-*.js`, ответ 404 здесь нормален)
и ставят `_stk_test_*`. В сборку этот код не попадает.

### Встроенная карта Яндекса убрана

Виджет содержит собственные счётчики Яндекса и грузился без согласия, поэтому с 05.11.2026 его на сайте нет.
Адрес и кнопка «Построить маршрут» ведут на карточку организации (`mapOrg` в `src/content/contacts.json`). До клика это обычная ссылка.
Вернуть виджет можно только через проверку согласия и после дополнения политики.

## Заявки и согласия

Формы на сайте три: окно заявки (`components/LeadModal.astro`), квиз (`components/home/Quiz.astro`), резюме (`components/ResumeModal.astro`).
Галочки — `components/Consent.astro`, проверка и отправка — `src/scripts/leads.ts`. Сейчас заявка только выводится в консоль браузера:
реальную отправку подключать в `submitLead()`.

### Правила форм

| Форма | Обязательные поля |
| --- | --- |
| Окно заявки | имя, телефон (11 цифр), сфера деятельности (только если вопрос показан), обе галочки |
| Квиз | имя, телефон; при выборе «Электронная почта» вместо телефона e-mail; обе галочки |
| Резюме | имя, телефон или e-mail, файл, обе галочки |

Комментарий нигде не обязателен. Файл резюме: `.pdf`, `.doc`, `.docx`, не пустой, до 10 МБ.

### Что нужно сделать на сервере

1. Заявки, файлы, журнал и CRM размещать только на серверах в РФ. Зарубежные сервисы для приёма форм не использовать (152-ФЗ, ст. 18, ч. 5).
2. Повторить на сервере все правила из таблицы. Проверка в браузере защищает от ошибок людей, но не от ботов.
   Заявку без обеих галочек не сохранять и никуда не передавать.
3. Файл резюме проверять по содержимому, а не только по расширению. Файлы не должны открываться по прямой ссылке без авторизации.
4. Добавить защиту от ботов: скрытое поле-ловушку и ограничение частоты запросов.
5. Заявку с файлом отправлять как `FormData`, а `consentRecord` передавать в ней строкой JSON.

### Журнал согласий

Доказать получение согласия обязан оператор (152-ФЗ, ст. 9, ч. 3; Политика, п. 1.6: получение, содержание, дата, способ).
Отдельно от CRM на сервере нужно вести журнал, куда запись добавляется при каждой отправке формы. Менять и удалять записи вручную нельзя.

В каждой заявке уже приходит `consentRecord`:

| Поле | Что содержит |
| --- | --- |
| `documents` | названия и редакции принятых документов (согласие и политика) |
| `texts` | точные тексты у галочек, которые видел человек |
| `page` | адрес страницы с формой |
| `acceptedAt` | время из браузера, только для справки |

Сервер добавляет сам: дату и время по своим часам (это основное время), IP-адрес, номер заявки, форму (`source`) и контакт из заявки.
Также нужно хранить копию каждой редакции документов с датой начала действия: редакция в записи должна вести к точному тексту.

### Сроки удаления по документам

| Данные | Срок | Где указано |
| --- | --- | --- |
| Заявка, только первичная консультация | не позднее 30 календарных дней после ответа по существу или документированного закрытия обращения | Согласие, раздел 5; Политика, п. 3.1 |
| Реестр деловых контактов в CRM, если сотрудник зафиксировал потенциал сотрудничества | 5 лет с момента согласия или до его отзыва | Согласие, раздел 5; Политика, п. 3.2 |
| Клиент перешёл к договору | по условиям договора | Согласие, раздел 5 |
| Резюме и данные соискателя | не более 6 месяцев с даты согласия | Согласие соискателя, раздел 5; Политика, п. 3.3 |
| Отзыв согласия | прекратить обработку и уничтожить данные в течение 10 рабочих дней, если нет иного законного основания | Согласие, раздел 6; Согласие соискателя; Политика, п. 3.3 |
| Журнал согласий | **в документах не указан**: цель, состав и срок нужно определить и внести в Политику до запуска | — |

Удаление должно охватывать все места хранения: CRM, почту, файлы резюме и резервные копии. Лучше настроить автоматическое удаление по датам и вести учёт уничтожения.

## Черновая ссылка на Netlify

Файл `netlify/edge-functions/site-password.ts` закрывает https://steklyanika.netlify.app паролем (настройка `SITE_PASSWORD` на Netlify).
На рабочем сервере в РФ он не нужен и в сборку `dist` не попадает. Заявки через Netlify не принимать: эта ссылка только для просмотра черновика.
